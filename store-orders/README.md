版本：`20261031-store-orders-r29`。完整雲端交接上線準備中；正式入口與正式產檔尚未開放，背景授權與訪客路徑保護已完成，仍須完成正式服務驗收。

## 使用流程

- 總部以公司帳號登入，讀取既有雲端商品主檔，發布只含貨號、品名與規格的門市查詢資料。原始 Excel 只在瀏覽器解析、不改原檔；成本不提供訪客。
- 總部按班次產生有期限、限制登入次數的門市邀請碼。PT不需email或公司帳號；每次訪客登入只能查看自己提交的單據，可上傳及覆核，不能結算或下載POS。
- 手機複選上傳完整單（JPEG、PNG、HEIC、多頁PDF，每檔20MB內）。原圖直接傳至公司Google Drive單檔上傳工作階段；多頁來源須明確加入同一單。
- 使用者確認公司授權後，完整單及局部細節圖片經Worker送至公司OpenAI API，以`gpt-6.1-sol`辨識（`store:false`）。請求會產生API費用。模型不取得商品主檔或成本；不採用未完成或部分結果，失敗可人工輸入。
- 依紙本位置核對表頭、貨號、主檔正式品名、數量、價格、組合代號、銷別、付款與成交總額。原紙本簡寫品名只輔助搜尋與辨識，不要求與主檔全文一致。來源完整與整單覆核兩項確認後可保存已覆核訂單。
- 組合代號至少兩列相同即同組；同組相同價格只計一次，不同價格須人工確認。新版一般價格是本列商品總金額，ERP單價＝本列總金額÷數量；整元不能精確守恆時阻擋，舊單仍依每件單價。組合只覆核整組總價，總部依確認的成本價乘數量比例拆為整元單價，精確保持整組金額；不能守恆時停止匯出。
- 總部核對完整清單、件數、頁數、金額與付款後結算。待補件、取消均須理由；新進來源不混入已確認批次。無單日須明確登記。
- 總部下載最終25欄`.xlsx` POS，人工匯入ERP，逐單登記建立結果。共用資訊與付款垂直合併，商品列與不同取貨倉庫保留。ERP已建立後鎖定，結果不明禁止重產，確認失敗才可重產。

`paper.html`為黑色A4空白訂購單，預設R14，單號由門市自填。欄位依序貨號、品名／規格、組合代號、數量、價格、銷別；新增會員編號，不列小計、已收、未收、頁碼、整單商品列數或導購。多頁使用相同單號，覆核時需確認所有來源及商品完整。

## 儲存與權限

使用公司指定的「POS單」個人雲端硬碟資料夾。沿用`siangstock-tools`既有Web OAuth Client，新增獨立密鑰但保留其他程式原密鑰。指定公司擁有者完成一次背景授權，回傳網址固定`https://siangstock.com/api/store-orders/oauth/callback`。Google授予Drive範圍，程式限制操作指定根目錄及本工具子資料夾；不使用全網域委派。

首次授權建立互不隸屬的R14待處理、總部結算、受限回收、商品查詢四個子資料夾。既有分享權限不自動修改；根目錄或子項目若含未確認公開、全網域、群組或未列名帳號即停止。訪客完全沒有Google Drive授權。

OAuth refresh token僅以AES-GCM密文存Cloudflare KV，與根目錄、擁有者及Client綁定；解密金鑰、OAuth密鑰、訪客簽章金鑰保存在Worker Secrets。瀏覽器不取得這些憑證，D1不保存憑證或完整訂單內容。

D1只保存流程索引、版本、隨機ID、檔案ID、內容雜湊、鎖、操作與邀請碼雜湊及稽核。姓名、電話、地址、明細、原圖、原始檔名不寫入D1或API日誌。辨識同店每天最多60次、同人同店只允許一個進行中請求；同操作不自動重送付費請求。

訪客Cookie限定`/api/store-orders-guest/`，HttpOnly、Secure、SameSite Strict；有效期最長12小時且不超過邀請碼期限。每次驗證同時檢查資料庫撤銷／期限。邀請碼只顯示一次、可逐碼停用所有已登入工作階段；來源IP僅用帶私密值的短期雜湊限流。

前端每60秒檢查新單，關閉分頁不背景執行。草稿以sessionStorage最多保留2小時，登出清除。雲端保存成功前不顯示已保存。版本不符／無法核對時停止關鍵操作、顯示重新載入最新版。

結算使用不可變快照、檔案雜湊與權限檢查及可重試分段提交。舊版本不覆寫，總部更正必須理由。ERP建立完成90天後整批移受限回收，不永久刪除；未完成30天列總部待辦，操作稽核12個月。
